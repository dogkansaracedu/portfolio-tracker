# Component 3: Platform & Asset Management — Technical (this build)
> Layer: React/Vite/Supabase implementation. Contract → [../03-platform-asset-management.md](../03-platform-asset-management.md)

## Stack
- React 19 + TypeScript, Vite. UI from shadcn/ui (Dialog, AlertDialog, Select, Table, Card, Badge, DropdownMenu, Input, Label, Button) + lucide-react icons + Tailwind 4.
- Data + auth via Supabase (Postgres). All reads filtered by `user_id` (RLS-backed).
- Shared server state via React Context providers (no react-query).

## File map

### Platforms
- `src/components/platforms/PlatformList.tsx` — grid of cards + "Add Platform"; owns the create/edit `PlatformForm` and the delete `AlertDialog`. Computes `assetCountByPlatform` from `useHoldings()` (counts holdings with `balance > 0`) and **blocks delete when the platform still has held assets**.
- `src/components/platforms/PlatformCard.tsx` — color dot + name + "N asset(s)" + actions menu (Edit / Delete).
- `src/components/platforms/PlatformForm.tsx` — `Dialog` with name `Input`, `PRESET_NAMES` quick-select chips (create only), and a `PRESET_COLORS` swatch palette (10 hex colors). Name is trimmed + required client-side.

### Assets
- `src/components/assets/AssetList.tsx` — splits assets into `ownedAssets` / `otherAssets` by net balance (sums `useHoldings()` balances per `asset_id` via `bn`/`BN_ZERO`, owned = `net.gt(0)`); renders owned first, the rest behind a collapsible "Not held (N)" row, twice from one model: `AssetRowCard`s below `sm` and the `Table` of `AssetRow`s from `sm` up. Owns the `AssetForm`, the deactivate `AlertDialog` and the `PriceSourcesDialog` (keyed by the asset id, so each open starts a fresh draft). Header shows `is_active` count / total. Gates write controls on `useIsAdmin()`: hides "Add Asset" and passes `canManage={isAdmin}` to each `AssetRow`. Mounted only by `src/pages/AdminPage.tsx` (route `ADMIN_ROUTE` = `/admin`, lazy), which renders a `Skeleton` while `useAuth().adminLoading` and `<Navigate to={ADMIN_FALLBACK_ROUTE}>` (`/`) for a non-admin. `SettingsPage` links to it for the admin only (`ADMIN_COPY`, `src/lib/constants/admin.ts`).
- `src/components/assets/AssetRow.tsx` — exports `AssetRow` (one table row) **and** `AssetRowCard` (the phone layout: icon + ticker/name and the actions menu in the card header, then the category/status/tag badges with the price right-aligned). Both read the shared `derivePrice` and render the shared `AssetPrice` / `AssetTags` / `AssetActions`, so the two layouts cannot drift. One table row: `AssetIcon` + ticker/name, category `Badge` (via `CATEGORY_LABELS`), price cell, tags as outline badges, status badge, actions menu. Price = `prices[asset.price_id ?? asset.ticker]`; native currency from `assetNativeCurrency(asset)`; fiat shows `1`; non-USD shows native value + `~$` from `price_usd`. Takes a `canManage` prop; renders its actions menu (Edit / Fiyat kaynakları / Deactivate; `onEditSources` opens the source editor) only when `canManage && is_active && !is_currency`.
- Both `AssetList` and `AssetRow` gate the write surface on `useIsAdmin()` (`src/hooks/useIsAdmin.ts`, returns `useAuth().isAdmin`, which `AuthContext` gets from the `is_admin()` RPC once per signed-in user) — the UI mirror of the database's admin-write boundary. `AuthContext` also exposes `adminLoading` (signed in, RPC not yet answered for this user id) so `AdminPage` doesn't redirect the admin on a cold load.

### Price sources (Fiyat kaynakları)
- `src/components/assets/PriceSourcesDialog.tsx` — `Dialog` (phone: full-height sheet; `DialogBody` scrolls the rows, `DialogFooter` pins Cancel/Save). On open (Yahoo/TEFAS assets only — `hasSourceList`) it calls `fetchPriceSources(asset.id)` and turns the rows into a draft (`toDrafts`). Rows: position, `PRICE_SOURCE_KIND_LABELS[source]` · symbol (`truncate`), health line from `sourceHealth` + `formatTimeAgo` (`line-clamp-2`, full error in `title`), and up/down/remove `icon-sm` buttons (`max-sm:size-10`). Add row: `Select` (`w-36`) + `Input` (`flex-1`, `maxLength` 32, Enter adds) + Add; `validateNewSource` guards it, the new row gets `crypto.randomUUID()` as its id. Save first folds a typed-but-not-added symbol in (same validation), then → `savePriceSources(asset.id, buildSourceSave(...))`; on failure the draft and the error stay. TCMB/manual assets get the `noList` line and a Close footer.
- `src/lib/priceSources.ts` — pure: `hasSourceList`, `toDrafts`, `moveDraft`, `validateNewSource`, `buildSourceSave` (dropped ids + one upsert list with `priority` = index + 1), `sourceHealth` (newer of `last_ok_at` / `last_error_at`). Tested in `src/lib/priceSources.test.ts`.
- `src/lib/queries/priceSources.ts` — `fetchPriceSources(assetId)` (`order priority`) and `savePriceSources(assetId, { deleteIds, upserts })`: delete the dropped ids, then **one** `upsert(rows, { onConflict: "id" })`. A single statement is a single transaction, so the deferred unique `(asset_id, priority)` is only checked after every row has moved; separate per-row updates would trip it mid-reorder. Health columns are never in the payload, so an upsert keeps them.
- `src/lib/constants/priceSources.ts` — `PRICE_SOURCES_TABLE`, `PRICE_SOURCE_KINDS` (value / label / example symbol), `PRICE_SOURCE_KIND_LABELS`, `DEFAULT_SOURCE_KIND` per category, `PRICE_SOURCE_LIST_ASSET_SOURCES` (`yahoo`, `tefas`), `PRICE_SOURCE_SYMBOL_MAX` (32, the DB check), `PRICE_SOURCE_COPY`.
- `src/lib/age.ts` — `formatTimeAgo` / `formatCompactAge`, shared with the header's `PriceRefreshButton`.
- `src/components/assets/AssetForm.tsx` — `Dialog` with category/price-source `Select`s, ticker, display name, icon URL (+ live `AssetIcon` preview), price id, tags `Input`. Category options come from `ASSET_CATEGORIES` (`src/lib/constants/assets.ts`, includes `fund`); `PRICE_SOURCES` / `TICKER_HINTS` for the rest. When `category === "fund"` it also renders an `at_source_tax_rate` number `Input` (fraction 0–1, e.g. `0.175`). On submit: requires ticker + name; validates the rate is a 0–1 fraction when non-blank; `price_id` empty ⇒ `trimmedTicker`; `icon_url` empty ⇒ `null`; `at_source_tax_rate` blank ⇒ `null` else `Number(...)`; tags split on comma → trim → lowercase → filter; always submits `is_active: true`. Create passes `is_currency: false`. The rate is threaded through `AssetInsert` / `AssetUpdate` (`src/types/database`) into the `createAsset` / `updateAsset` queries.

## Data layer
Only Component-2 tables. The one schema addition this surface writes is the nullable `at_source_tax_rate numeric` column on `assets` (migration `supabase/migrations/20260608000000_asset_at_source_tax_rate.sql`) — a fraction like `0.175` withheld at source on the asset's gains; `null` for assets with no at-source tax. The P&L engine consumes it (see Component 6); this surface only edits it. The price-source editor reads and writes `asset_price_sources` (migration `supabase/migrations/20261118000000_asset_price_sources.sql`: `asset_id`, `priority` ≥ 1 with a deferrable unique `(asset_id, priority)`, `source`, `symbol` 1–32, `last_ok_at` / `last_error` / `last_error_at`; select for any signed-in user, insert/update/delete admin only).
- `src/lib/queries/platforms.ts` — `fetchPlatforms` (`order created_at`), `createPlatform`, `updatePlatform`, `deletePlatform`. Plain `supabase.from("platforms")` calls.
- `src/lib/queries/assets.ts` — `fetchAssets` (`select *`, `order name`, **no `user_id` filter** — the catalog is global), `createAsset`, `updateAsset`, `deactivateAsset` (sets `is_active = false`). Also hosts `resolveTickers()` (calls the `resolve-tickers` Edge Function, which requires a signed-in user — 401 otherwise — before its service-role `price_cache` write) used by import elsewhere — not part of this CRUD surface. (The function's `{ query }` symbol-search path is no longer called by the app — the watchlist picks catalog assets now, see [19-watchlist](19-watchlist.md).) `fetchAssets()` has a second call site: `src/components/transactions/sheet/autoResolveSentinels.ts` (duplicate-ticker race recovery).
- `src/contexts/PlatformsContext.tsx` / `src/contexts/AssetsContext.tsx` — providers holding the single shared fetch + optimistic-ish mutators (`add/edit/remove` for platforms; `add/edit/deactivate` for assets, which `refetch()` after each write). `AssetsContext.refetch` calls `fetchAssets()` with no argument. Exposed via `usePlatformsContext` / `useAssetsContext`.
- `src/hooks/useAssets.ts` / `src/hooks/usePlatforms.ts` — **thin re-exports** of the context hooks, preserving the original import paths. They are NOT fetch-on-mount hooks.

## Notes & gotchas
- **Assets are a global catalog, not per-user.** RLS on `assets` is `SELECT USING (true)` for all authenticated + INSERT/UPDATE/DELETE gated to `public.is_admin()`, i.e. membership in `public.app_admins` (migrations `20260610000000_global_asset_catalog.sql`, `20261117110000_app_admins.sql`). The UI gate `useIsAdmin()` asks the same function — RLS is the real boundary, the UI gate is convenience. Platforms remain per-user. (Note: implicit asset creation during transaction import — `autoResolveSentinels` → `createAsset` — therefore only succeeds for the admin.)
- **Shared fetch, not per-call-site:** assets and platforms are fetched once in the providers and shared. Fetching on mount inside `useAssets`/`usePlatforms` instead would fire one identical `?select=*` request per call site (`AppLayout`, filters, bulk sheet, settings) on every page. Do not reintroduce per-component fetching; consume the context.
- **`price_id ?? ticker` fallback** appears in two places that must agree: `AssetForm` coalesces empty → ticker on save; `AssetRow` reads `prices[asset.price_id ?? asset.ticker]`. Keep them aligned.
- **`price_id` auto-derive:** `AssetForm` uses `derivePriceId(ticker, category, source)` (`src/lib/priceId`) and a `priceIdDirty` flag — it stays synced to the ticker until the user hand-edits the field, then their value is preserved. On open, a stored id that equals the derived value stays "clean" (keeps syncing); anything else is treated as a manual override.
- **Logos are token-free by project convention:** `LOGO_BASE` points only at public GitHub repos served over the jsDelivr CDN (ahmeterenodaci BIST/Nasdaq/NYSE logos, spothq `cryptocurrency-icons`) and HatScripts `circle-flags` for fiat — no API-key services (no logo.dev etc.). Crypto/gold may legitimately have no logo and fall to the monogram. Escape hatch if a repo goes stale: fork it and point `LOGO_BASE` at the pinned fork.
- **Native currency comes from the asset, not the price columns:** the price fetch back-fills both `price_usd` and `price_try` for every asset, so currency must be derived via `assetNativeCurrency` (see `src/lib/constants/assets.ts`), not inferred from which column is non-null.
- **Currency assets** (`is_currency`) have no edit/deactivate menu in `AssetRow` and price as `1`; they're maintained as part of the currency set, not via this CRUD.
- **Soft vs hard delete:** assets soft-delete (`is_active = false`) because transactions/holdings FK them; platforms hard-delete but only when no held asset references them (guard is computed in `PlatformList` from holdings, not enforced as a DB constraint here).
- **`AssetIcon` failure tracking is keyed by URL** (not candidate index) so a recycled component instance stays correct when a list re-renders for a different asset.
- Shipped `PRICE_SOURCES` are `yahoo` / `tcmb` / `tefas` / `manual`. The `coingecko` value named in the [glossary](../GLOSSARY.md#asset) is not among them — crypto prices via `yahoo`.
