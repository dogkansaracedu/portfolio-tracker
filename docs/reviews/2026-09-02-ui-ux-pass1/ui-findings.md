# UI review — pass 1 (desktop, 1440×900 light; spot-checked 1280×800 and dark)

Reviewer lens: visual/interface (hierarchy, numerics, alignment, color, component idiom, charts, cross-page consistency, theming). Screenshots in `shots/ui/`; file paths below are relative to `src/`. Computed-style figures were read from the DOM with Playwright (`pw/ui-pass3.mjs`, `pw/ui-pass4.mjs`).

---

### UI-01 · high · Transactions table (and the same table on Asset Detail) — numeric columns are left-aligned and proportional, unlike every other table in the app
- Evidence: `shots/ui/04-transactions.png`, `shots/ui/12-transactions-tall.png`, `shots/ui/18-asset-tp2-tall.png` ; `components/transactions/TransactionList.tsx:55-57` (Quantity / Unit Price / Total `<TableHead>` with no `text-right`), `components/transactions/TransactionRow.tsx:77-103` (cells with no `text-right`; Quantity cell at `:77` has no `tabular-nums` either). DOM: `text-align: start` on all three columns; the Portfolio table's Quantity/Bought/Price/Value cells are `text-align: right` + `tabular-nums` (`PortfolioRow.tsx`).
- Why it matters: "4.9056", "35,040.994223" and "-105.7231" stack with their first digit aligned, so magnitudes cannot be compared down the column — the one thing a broker log's numeric columns are for — and the same user sees the opposite convention one click away on Portfolio.
- Proposed change: right-align Quantity, Unit Price and Total (head and cell) and add `tabular-nums` to the Quantity cell, matching `PortfolioRow`. Keep the approximate-USD sub-figure as a right-aligned second line so the native amount stays the anchor.

### UI-02 · high · Transaction editor header — "Import" and "Import from Midas" render white-on-white and are effectively invisible in light mode
- Evidence: `shots/ui/50-txedit-top.png`, `shots/ui/51-txedit-type-cell.png` (light) vs `shots/ui/86-dark-txedit.png` (dark, legible) ; `pages/TransactionsEditPage.tsx:40` (header sets `text-zinc-100`), `components/transactions/sheet/ImportPopover.tsx:74` and `components/transactions/sheet/MidasPdfImportButton.tsx:126` (`<Button variant="outline" size="sm">` with no color override), while the neighbouring "Add row" button gets `border-zinc-700 bg-zinc-800 text-zinc-100` at `TransactionsEditPage.tsx:49-53`. Computed: background `oklch(1 0 0)`, text `oklch(0.967 …)`, `disabled: false`.
- Why it matters: the two bulk-import entry points — the reason this page exists — look like blank pills; the user has to know they are there.
- Proposed change: give the two import triggers the same dark-header outline treatment as "Add row" (or lift a shared `headerButtonClass` constant so all three stay in sync); alternatively drop the inverted header entirely (see UI-09).

### UI-03 · high · App-wide — a single-select segmented control is drawn six different ways
- Evidence: `shots/ui/02-dashboard.png` (Value|Performance: white pill + shadow on grey track, `components/dashboard/DashboardHero.tsx:459`; range 1D…ALL: solid primary, `:845`), `shots/ui/03-portfolio.png` (Total|Daily, Platform|Category: shadcn `ToggleGroup variant="outline"`, `components/portfolio/PortfolioFilters.tsx:56-83`), `shots/ui/04-transactions.png` (date presets: `Button variant={active ? "default" : "outline"}`, `components/transactions/TransactionFilters.tsx:136`; type chips: bespoke bordered chips with per-type color, `components/transactions/TransactionTypeSelector.tsx:22`), `shots/ui/06-retirement.png` (Nominal|Real, Capital preservation|depletion, question chips: bespoke `bg-primary text-primary-foreground`, `components/retirement/RetirementControls.tsx:164`; Plan|Compare: shadcn Tabs), `shots/ui/18-asset-aapl-tall.png` (Cost/Price/range: bespoke `bg-primary`, `components/asset-detail/AssetHistoryChart.tsx:67,78`), `shots/ui/71-settings-snapshots.png` (granularity: `border-primary bg-primary/10 text-primary`, `components/settings/SnapshotBackfillCard.tsx:102`). Computed active states: `bg-background + shadow-sm` / `bg-primary` / `bg-muted` (outline ToggleGroup) / `bg-primary/10 + border-primary`.
- Why it matters: the same interaction ("pick one of these") has no recognisable shape, so the eye re-learns the control on every page; solid-primary pills in particular read as primary CTAs (the same green as "Add Transaction"), which is why the Asset Detail chart row appears to have three simultaneously "active" buttons (UI-10).
- Proposed change: standardise on one primitive for view/mode/range selection — the shadcn `ToggleGroup` already used on Portfolio (outline track, subtle active fill) — and reserve solid `bg-primary` for the single primary action on a page. The hero's white-pill variant may stay as the one "segment" style if the outline ToggleGroup is restyled to match it; either way, two idioms at most.

### UI-04 · medium · Transactions — the gain/loss palette is applied to non-gain/loss figures, and with a drifted hue
- Evidence: `shots/ui/04-transactions.png` (Buy Volume green / Sell Volume red; Sell row: red quantity "-105.7231" next to green realized "₺8.693,23"), `shots/ui/40-tx-filter-buy.png` ("Sell Volume $0.00" in red) ; `components/transactions/TransactionSummary.tsx:31,44` (`gainLossClass(true)` / `gainLossClass(false)` hard-wired to the card, not to any sign), `components/transactions/transactionRowModel.ts:94-98` (quantity color hand-rolled as `text-green-600` / `text-red-600` — not `gainLossClass`, whose palette is `emerald-600` / `red-500`).
- Why it matters: on a sell row the user sees red (quantity left the account) and green (the sale made money) in the same 40px — two meanings for one palette — and a $0 sell volume painted red reads as a loss; the drifted `green-600` also fails the app's own "one convention" rule.
- Proposed change: render Buy/Sell Volume in the default foreground (they are volumes, not results); render quantity in the default foreground with its ASCII sign carrying direction (the Type badge already colours buy/sell), or if a colour is kept, route it through `gainLossClass`.

### UI-05 · medium · Portfolio / Asset Detail — a zero result is painted green
- Evidence: `shots/ui/18-asset-aapl-tall.png` and `18-asset-xau-tall.png` ("Realized P&L $0.00" in emerald), `shots/ui/30-pf-daily.png` (USD row "Today $0.00 / 0.00%" in emerald) ; `components/asset-detail/AssetPositionSummary.tsx:51,83,172,190` (`gainLossClass(x >= 0)`), `components/portfolio/PortfolioRow.tsx:107,275` (`netIsPositive = netUsd >= 0`), `components/portfolio/PortfolioGroupHeader.tsx:39`.
- Why it matters: the app's stated convention is "zero shows no sign, neutral"; a green $0.00 tells the user something was earned when nothing was, and it is exactly the case a flat cash row hits every day.
- Proposed change: treat zero as neutral at the call sites (`value > 0 ? gain : value < 0 ? loss : ""`), or extend `gainLossClass` with a tri-state signature so every surface inherits it.

### UI-06 · medium · Portfolio group headers — subtotal figures do not sit in the Value / P&L columns they summarise
- Evidence: `shots/ui/03-portfolio.png`, `shots/ui/11-portfolio-tall.png` ("Fiat … $18,623.61  -$173.90" right-flushed to the row edge) ; `components/portfolio/PortfolioGroupHeader.tsx:43-58` (one `colSpan` cell, `flex justify-between`, `gap-4`). DOM at 1440: header content right edge x=1416; Value column right edge x=1205; P&L column right edge x=1299.
- Why it matters: the header exists so the eye can add a group's rows to its subtotal; with the subtotal ~200px to the right of the Value column and the P&L subtotal under the Alloc column, that check has to be done by reading, not by scanning.
- Proposed change: render the group header as real cells (empty cells for Asset…Price, subtotal in the Value cell, return in the P&L cell, empty Alloc/action cells) so both figures land in their columns in every grouping and both return modes.

### UI-07 · medium · Dashboard hero (Performance) — the benchmark line is near-invisible, there is no legend, and the y-axis ticks are not round
- Evidence: `shots/ui/02-dashboard.png`, `shots/ui/22-dash-1Y.png`, `shots/ui/22-dash-ALL.png`, `shots/ui/80-dark-dashboard.png` ; `components/dashboard/DashboardHero.tsx:786-791` and `:813-816` (benchmark `stroke="var(--muted-foreground)" strokeWidth={1} strokeOpacity={0.45}`), `:329-345` + `:715-716` (custom `pctTicks` yielding 3.2 / 2.1 / 1.1 / 0 / −1.1 % and 17.4 / 13.1 / 8.7 / 4.4 %), no `<Legend>` anywhere in the file.
- Why it matters: the headline promise of this card is "you vs the index", but the index is a 1px 45%-opacity grey hairline that disappears in the 1M range and on dark; and non-round ticks ("2.1%", "8.7%") make the gridlines unusable as reference levels.
- Proposed change: draw the benchmark as a 1.5–2px line in a dedicated neutral (e.g. `--chart-4` or a mid slate) and add a two-item inline legend under the subtitle (portfolio colour dot + "You (TWR)", grey dot + benchmark name); compute ticks with a nice-number step (0.5 / 1 / 2 / 5 …) instead of dividing the domain evenly.

### UI-08 · medium · Number and date formatting mixes locales within one row and one page
- Evidence: `shots/ui/12-transactions-tall.png` (TP2 row: quantity `35,040.994223` en-US beside total `₺186.657,52` tr-TR; EUR row Jan 15: `500,00 €` symbol-after beside `$556.50` symbol-before), `shots/ui/24-dash-hero-tooltip.png` ("21 Ağustos 2026", axis "Ağu 2026", "Şimdi") vs "Aug 28, 2026" on Transactions ; `lib/config.ts:59-61` (USD `en-US`, TRY `tr-TR`, EUR `de-DE`), `components/dashboard/DashboardHero.tsx:396-402,746-749`, `hooks/useDashboardHero.ts:146-151`, `lib/dashboard/intraday.ts:39,78` (all `tr-TR`).
- Why it matters: in a numeric table the same glyph "," means thousands in one column and decimals in the next, which is a misread waiting to happen; and a UI whose every label is English switching to Turkish month names only inside the chart looks unfinished rather than localised.
- Proposed change: pick one numeric locale for the whole UI (en-US grouping with the ₺/€ symbol prefixed, as the ₺ column already partially does) and one date locale for axes/tooltips matching the tables (en-US short month); "Şimdi" → "Now" unless the whole UI goes Turkish. This is a formatting-layer change in `formatCurrency` and the hero date helpers, not a data change.

### UI-09 · medium · Transaction editor — a different product's chrome
- Evidence: `shots/ui/51-txedit-type-cell.png`, `shots/ui/52-txedit-bottom.png` ; `pages/TransactionsEditPage.tsx:40,100` (`bg-zinc-900 text-zinc-100` header and footer), `:139` (Save `bg-amber-400 text-zinc-900` — computed `oklch(0.828 0.189 84)`; the app's primary everywhere else is emerald), `components/transactions/sheet/TransactionsSheetGrid.tsx:482-509` (column heads `text-xs uppercase tracking-wide`, used nowhere else), `components/transactions/sheet/cells/DateCell.tsx:14` (native `type="date"` shows `02.09.2026`) under a header hint reading `YYYY-MM-DD` (`TransactionsSheetGrid.tsx:491`).
- Why it matters: leaving the sidebar app for a black-barred, yellow-buttoned full-screen sheet feels like a third-party tool; the mustard Save competes with, rather than continues, the emerald primary, and the date column promises one format while displaying another.
- Proposed change: keep the full-screen layout but use the app's surface tokens (`bg-card` / `border-b`) for header and footer, the standard primary Button for Save, Title-case column heads like the Transactions table, and either drop the `YYYY-MM-DD` hint or show the ISO string in the cell.

### UI-10 · medium · Asset Detail — no visual hierarchy: eight stats at one size, the live price whispering, and three "active" green pills in the chart row
- Evidence: `shots/ui/18-asset-aapl-tall.png`, `shots/ui/18-asset-btc-tall.png` ; `components/asset-detail/AssetPositionSummary.tsx:28-29` (every `Stat` value `text-sm font-semibold`, label `text-xs`), `components/asset-detail/AssetDetailHeader.tsx:50` (price `text-sm`, weight 400 — computed 14px/400, same size as the ticker badges), `components/asset-detail/AssetHistoryChart.tsx:67,78` (Cost/Price toggles `bg-primary` — identical to the active range button), `:98` (`<XAxis>` with no `minTickGap`/`interval` → 28 abutting tick labels across 1100px).
- Why it matters: on the one screen dedicated to a position, Value and Total return are visually equal to Quantity and Allocation, the current price is the smallest text on the header, and the chart controls look like three selected states — the user has to read everything to find the number they came for.
- Proposed change: promote Value and Total return (e.g. `text-xl font-semibold`) and demote Quantity/Allocation/Avg cost to the current size; set the header price at the same weight as the Portfolio row price; style Cost/Price as toggles distinct from the range selector (outline ToggleGroup per UI-03); add `minTickGap={40}` (or `interval="preserveStartEnd"`) to the x-axis.

### UI-11 · medium · Retirement — projected-value chart: marker labels collide and the axis wastes a −$20M band
- Evidence: `shots/ui/13-retirement-tall.png`, `shots/ui/84-dark-retirement.png`, `shots/ui/93-1280-retirement.png` ("Retirement age 6Earliest retirement: 62" overprint in all three; y-axis −$20M…$60M with "Retirement target" sitting on the $0 line) ; `components/retirement/PlanChart.tsx:168-190` (labels `position: "insideTop"` and `"insideTopRight"` on two `ReferenceLine`s two years apart), `:106-112` (`<YAxis>` with default auto domain), `:149-158` (target `ReferenceLine` label `insideTopLeft`).
- Why it matters: the two ages are the answer to "when can I retire?" and they are unreadable when they are close — which is the common case; and a projection that is never negative giving 25% of its height to negative values squashes the base case and the target into the bottom gridline.
- Proposed change: clamp the y-domain at `[0, 'auto']` (or `dataMax` of the optimistic band) and place the two age labels on opposite sides of their lines (`insideTopLeft` for retirement age, `insideTopRight` for earliest) or stack them vertically (`dy`) when within N years; give the target line a label that carries its value ("Target $1.4M").

### UI-12 · medium · Dashboard — the same currency wears a different colour in two adjacent cards
- Evidence: `shots/ui/10-dashboard-tall.png` (Allocation legend: TRY green, USD teal, EUR blue-cyan; Currencies card: USD blue, TRY amber, EUR violet; Allocation's US Stocks blue equals the IBKR platform dot blue) ; `components/dashboard/AllocationChart.tsx:29-35` (TRY `#16a34a`, USD `#0d9488`, EUR `#0891b2`) vs `components/dashboard/CurrencyBreakdown.tsx:11-15` (USD `#3b82f6`, TRY `#f59e0b`, EUR `#8b5cf6`), `AllocationChart.tsx:13` (stock_us `#3b82f6`).
- Why it matters: colour is the only key the donut has; when TRY is green in one card and amber in the next, and "blue" means both US Stocks and IBKR, the reader cannot carry a colour across the page.
- Proposed change: one shared currency palette constant consumed by both `AllocationChart` (outer fiat ring) and `CurrencyBreakdown`; pick category hues that do not collide with the platform colours already assigned in Settings (blue is IBKR, so US Stocks should not be blue).

### UI-13 · medium · Portfolio at 1280×800 — the Alloc and action columns are clipped off-screen
- Evidence: `shots/ui/91-1280-portfolio.png` ("Allo", "10.6", the "+" column gone) ; `components/ui/table.tsx:11` (`overflow-x-auto` wrapper). DOM at 1280: table `scrollWidth 1055` inside a `clientWidth 992` container; main area does not scroll horizontally, so the overflow is only discoverable by dragging inside the table.
- Why it matters: 1280 is a normal laptop width; the daily user loses the allocation column and the per-row add-transaction affordance with no visible scrollbar cue.
- Proposed change: budget the columns for ~990px — shorten "Bought"/"Price" cells by moving the `(~$x)` USD equivalent to a second line (as the Transactions total already does), and let the Platform column truncate — so the table fits without horizontal scroll down to 1280.

### UI-14 · low · Status badges — "Ends soon" is amber on Portfolio/Asset Detail but a neutral grey pill on Campaigns
- Evidence: `shots/ui/15-campaigns-tall.png` (ETH, XAUT cards) vs `shots/ui/18-asset-try-tall.png` and `shots/ui/03-portfolio.png` (amber outline "% 39.5%") ; `pages/CampaignsPage.tsx:366` (`<Badge variant="secondary">`), `lib/constants/interest.ts:61,71` (`border-amber-500/40 text-amber-700 …` for `ends_soon`).
- Why it matters: the same 7-day warning state is a colour on one page and not on another; the campaign deadline the user is most likely to miss is the one that is not highlighted.
- Proposed change: reuse the interest `ends_soon` tone (or a shared `statusToneClass`) for the Campaigns badge; keep `secondary` for program type only.

### UI-15 · low · Return percentages switch between 2 and 1 decimals for the same figure
- Evidence: `shots/ui/18-asset-thyao-tall.png` (card "Realized P&L −$10.55 (−3.08%)" and, below it, the sell row "~−$10.55 (−3.1%)"), `shots/ui/02-dashboard.png` ("1.51%" headline, "7.9%/yr", "0.9 pts") ; `components/transactions/transactionRowModel.ts:132` (`toFixed(1)`, bypassing `formatSignedPercent`), `components/dashboard/DashboardHero.tsx:610,629` (`formatSignedPercent(…, 1)`), everywhere else default `DECIMALS.percentage = 2` (`lib/config.ts:23`).
- Why it matters: two precisions for one number on one screen reads as two numbers; a broker-grade table keeps one precision per figure type.
- Proposed change: route the realized % through `formatSignedPercent()` at the default precision; if 1dp is intentional for annualised/points figures, document that as the rule (return % = 2dp, allocation % and %/yr = 1dp) in `lib/config.ts` so it stops drifting.

### UI-16 · low · Login card — the footer band butts against the password field
- Evidence: `shots/ui/01-login.png` (grey footer with `border-t` starting flush under the password input, visually clipping it) ; `components/auth/LoginForm.tsx:47-93` (`<form>` wraps `CardContent` + `CardFooter`, so the Card's `gap-4` — `components/ui/card.tsx` `Card` — no longer separates them; `CardFooter` adds `border-t bg-muted/50`).
- Why it matters: it is the first screen every session and it looks broken.
- Proposed change: add `space-y-4`/`gap-4` on the `<form>` (or `mt-4` on the footer) so the footer keeps the Card's spacing rhythm; or drop `CardFooter` and put the button inside `CardContent` like the signup form should.

Also noted (not ranked): Settings › Assets shows 20 solid-primary "Active" badges (`components/assets/AssetRow.tsx:91`) — status noise in the primary colour — and "fund" is the only lowercase category label (`AssetRow.tsx:16` map lacks `fund`); the Portfolio Alloc mini-bar is scaled to 100% so every bar is a 1–7px nub (`components/portfolio/PortfolioRow.tsx:217-220`); the Value-mode hero on 1M shows only two x-axis labels ("Ağu 2026", "Şimdi") where 1Y shows monthly; the Campaigns card grid does not align card footers within a row (`shots/ui/15-campaigns-tall.png`).

Not reviewed: `/signup` (not screenshotted — brief scopes it to a glance and login was the only auth screen exercised); the delete-confirmation dialog and edit sheet from the Transactions row menu (menu opened and closed only, to stay read-only); loading skeletons and empty states (cannot be induced on the seeded dataset without mutating data); hover/focus-ring states beyond the benchmark chip focus ring visible in `shots/ui/24-dash-hero-tooltip.png`; `/more`, `/performance` and mobile viewports per brief.

Positives: (1) the Portfolio table row typography is the strongest thing in the app — muted Bought vs dark Price vs bold Value, amount-over-percent P&L stack, right-aligned `tabular-nums` — and should be the template the Transactions table is brought up to, not the other way round; (2) dark mode parity is genuinely good — no light-only colours or unreadable text were found on any reviewed page except the editor header (UI-02), and the amber/emerald/red tokens all hold contrast on dark; (3) the Value-mode hero and the three summary cards (Portfolio, Transactions) have a clean label-over-figure scale that the rest of the pages should inherit rather than replace.
